# Upgrade riešenia eCommerce na .NET 10 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Presunúť všetkých 15 projektov v `src/eCommerce.sln` z `netstandard2.1`/`net6.0` na `net10.0` a zdvihnúť všetky NuGet balíčky na najnovšie stabilné verzie kompatibilné s .NET 10, pričom riešenie musí zostať buildovateľné (0 errorov) po každej dokončenej úlohe.

**Architecture:** Ide o interné integračné riešenie (worker services + konzolové importy + zdieľané knižnice) bez externých spotrebiteľov NuGet balíkov na iných frameworkoch — preto všetkých 15 projektov prechádza jednotne na `<TargetFramework>net10.0</TargetFramework>` namiesto zachovania `netstandard2.1` pre knižnice. Keďže vyšší TFM vie referencovať nižší (net10.0 projekt môže mať `ProjectReference` na netstandard2.1/net6.0 projekt), poradie úloh nižšie ide zdola nahor (najprv "listové" knižnice bez balíčkov, potom projekty s balíčkami, napokon spustiteľné aplikácie) len pre prehľadnosť — nie je to tvrdá závislosť pre buildovateľnosť. Balíčky `Microsoft.Extensions.*` prechádzajú z `7.0.0` na `10.0.11` (major verzia balíka teraz kopíruje major verziu runtime), ostatné balíčky idú na najnovšiu stabilnú (non-preview) verziu z NuGet.org. Balíček `System.Text.Encoding` (4.3.0) sa odstraňuje — jeho funkcionalita (trieda `Encoding`) je súčasťou BCL od .NET 5 a na `net10.0` je balíček nadbytočný; `System.Text.Encoding.CodePages` ostáva (skutočne používaný pre `CodePagesEncodingProvider`/`windows-1250` v `Pohoda.Server`), len sa zdvihne verzia.

**Tech Stack:** .NET 10 SDK (overené nainštalované: `10.0.400`), MSBuild SDK-style `.csproj`, `Microsoft.NET.Sdk` a `Microsoft.NET.Sdk.Worker`. V riešení dnes neexistujú žiadne testovacie projekty — overenie správnosti = úspešný build (0 errorov), nie prechod testov.

**Spec:** Priama požiadavka používateľa (slovensky): "naplánuj upgrade solution na najnovší .NET 10, tiež sprav upgrade balíčkov na najnovšie vhodné verzie pre .NET 10" + doplnenie "presvedč sa, že solution a projekty sú stále buildovateľné po upgrade." Žiadny predchádzajúci spec dokument neexistuje — aktuálny stav bol zistený prieskumom repozitára (pozri zistenia nižšie).

### Zistený súčasný stav (dôkazy)

- `src/eCommerce.sln` obsahuje 15 projektov (overené porovnaním `.sln` so všetkými `.csproj` v `src/`).
- `src/Common/Contract/Common.Contract.csproj` (bez podpriečinka) je **osirotený súbor** — nie je referencovaný v `.sln`, nepatrí do buildu. Tento plán sa ho nedotýka.
- Cieľové frameworky pred zmenou: 9× `netstandard2.1`, 6× `net6.0`.
- Baseline build bol overený pred písaním plánu: `dotnet build src/eCommerce.sln -c Release` → **0 Errors, 345 Warnings** (všetky warningy sú pred-existujúce `CS86xx` nullable-warnings a 2× `CS0169` unused field — žiadny projekt nemá `TreatWarningsAsErrors`, takže tieto warningy build nezastavia). Toto číslo (345) slúži ako referenčná hodnota — po upgrade sa počet warningov môže mierne zmeniť (nové analyzer pravidlá v novšom SDK), ale **0 Errors musí platiť vždy**.
- `README.md` (riadky 17-19) explicitne popisuje "novšie aplikácie: .NET 6.0" a "staršie knižnice: .NET Standard 2.1" — po upgrade je táto informácia nesprávna a treba ju opraviť.
- `CI/azure-pipelines.yml` je zastaraný template pre klasický ASP.NET (.NET Framework) web-deploy (VSBuild/IIS), nepoužíva `UseDotNet@2` ani neuvádza konkrétnu SDK verziu — nevyžaduje zmenu v rámci tohto plánu (mimo rozsahu, nie je aktívne naviazaný na tieto projekty).
- Zdrojové verzie balíčkov overené v `.csproj` súboroch, cieľové verzie overené priamym dotazom na NuGet.org flat-container API (`https://api.nuget.org/v3-flatcontainer/<pkg>/index.json`) dňa 2026-08-19.
